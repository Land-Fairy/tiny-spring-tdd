## 三、P1

1. `DisposableBeanAdapter.java:105` / `:113` / `:132` 三处 `catch (Exception ignored)`：类注释 `:21-24` 解释了「本书没有日志设施」，但没解释为什么连「哪个 Bean 销毁失败」都不收集。**建议**：把失败的 BeanName 收集进一个返回列表或抛聚合异常——这既不加依赖，也把「可追溯」这条要求做到位。
2. `beans/factory/support/DestroyTests.java:57-68`「销毁之后两个池都空了」只观测单例池（E2）；销毁表 `disposableBeans` 没有公开入口，从未被断言——第二个池漏清空照样绿。
3. `InitMethodTests.java:53-66`：catch 掉异常后只断言 `containsSingleton` 为 false，若 `getBean` 压根没抛，测试仍绿（E2）。
4. 「三条初始化通道」「装配总览：一个单例的完整旅程」是自创词，建议对齐 `GLOSSARY.md` 的「初始化的回调接口」「生命周期」。

## 四、读者会在哪一段放弃

「销毁顺序与初始化相反」这一句。这是本章最想教的心智模型，也是**唯一一处三份材料各说一套**的地方（代码注释说相反、文档说镜像、代码本身是同向）。读者若照注释去推「谁最后准备谁最先走」，在真实 Spring 里 debug 时会彻底找不到北。

## 五、总判词

本章的**代码**质量是全批最好的之一：`InitDestroyAnnotationBeanPostProcessor` 124 行吃掉上游 489 行，`DisposableBeanAdapter` 149 行吃掉 559 行，三条通道（注解 / 接口 / XML 属性）各归各位，没有互相渗透。失分全在**叙述**：顺序讲反（C1）、机制编造（A1）、注释停在上一章（C2）、体量表对着别的副本抄（B2）。这一章值得单独做一次「注释与代码逐句对账」。
