## 三、P1

1. **两条测试逐字相同**（E1，我逐行比对过）：
   - `step-05-…/support/PropertyPopulationTests.java:51` `noPropertyValuesMeansNoSetters`（「没有配置属性时 setter 一次都不跑」）
   - 同文件 `:82` `failingInitializingCallbackIsWrapped`（「初始化回调抛异常：同样被包成 BeanCreationException」）

   两个方法都只是 `registerBeanDefinition("service", service(new MutablePropertyValues()))` + `assertThatThrownBy(getBean).isInstanceOf(BeanCreationException.class).hasMessageContaining("afterPropertiesSet").hasRootCauseMessage("prefix must be set before use")`——**完全一致**。两条测试在测同一个失败路径，`@DisplayName` 承诺的「setter 一次都不跑」与「回调异常被包住」都没有被分别断言。这不是「断言恒真」（E 类），而是**重复覆盖 + 名不副实**（P1）。修法：前者补 `assertThat(service.settersInvoked()).isEmpty()`，后者保留现有的根因断言。

2. 「属性填充」这条链路里，`BeanWrapperImpl` 的类型转换异常被包了两层（`TypeMismatchException` → `BeanCreationException`），书上只讲了一层；新手在真实 Spring 里 debug 时会少找一层。

## 四、读者会在哪一段放弃

`PropertyValue` 只有三个 `private final` 字段、没有 setter，`:296` 已经预判了「这不就是 `record` 吗」的疑问并给出了回答——这说明作者知道读者会卡在哪，是本批里少见的「预判式写作」。放弃点不在这里，而在两条同名不同实的测试上：读者若照抄其中一条当模板，会学到一个「看起来在测 setter，其实什么都没测」的形状。

## 五、总判词

本章是「从动作到数据」的转折点：`PropertyValue` 90 行把「要填什么」变成不可变的键值事实，`MutablePropertyValues` 负责收集，`BeanWrapperImpl` 负责填，三层职责不重叠，是新手里最值得抄的一章。唯一的硬伤是一个手抄的数字（已由机器闸门挡住），唯一的软伤是两条重复测试。
