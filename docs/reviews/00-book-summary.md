# 全书评审总评（ch01–ch35）

**评审对象**：`tiny-spring-tdd` 全 35 章（每章一个 `step-NN-*` 模块，累计 305 个主源文件 / 约 1.8 万行主代码 + 446 个 `@Test`）
**判据**：`docs/reviews/00-criteria-card.md` v1.1（六视角 × P0/P1 分类 × 判决规则）
**方法**：每章六视角（可跑 / 生产可用 / 变异实证 / 模块深度 / 术语 / 文档结构）+ 9 道机器闸门
**结论一句话**：**结构可以照抄，说法不能全信。** 35 章的设计与分层经得起看；出错的地方几乎全在「旁证」——行数、栈帧、测试名、上游行号、跨章承诺。

## 一、110 条 P0 的分布（这是全书最有用的一张表）

| 类别 | 含义 | 条数 | 判决影响 |
| --- | --- | --- | --- |
| **B** 量化矛盾 | 行数 / 条数 / 字段数 / 次数与实际不符 | **44** | FAIL |
| **A** 虚构引用 | 指向不存在的类、方法、行号、上游事实 | **25** | FAIL |
| **C** 语义契约 | 行为与自身注释 / 消息 / 命名不一致 | **20** | 可 WITH-FIXES |
| **E** 闸门失效 | 断言恒真、空集放行、脚本单边检测 | **13** | 可 WITH-FIXES |
| **D** 兑不了的教学承诺 | 承诺后续章节兑现，实测到 step-35 未兑现 | **8** | FAIL |

读法：**B + A = 69 条，占 63%**，全部是「说的是真的吗」这一类，而不是「设计好不好」。这不是巧合——教材最容易烂的地方是旁证，因为旁证是手抄的，代码是会动的。

## 二、反复出现的五种形状（比单条缺陷更值得记）

1. **手抄数字必漂移。** 35 章体量表共 14 张、169 个数字，一次成型时错了 24 个。→ 已做成闸门 9（`scripts/check-doc-tables.py`，`--fix` 可自动回写）。
2. **引用必虚构。** 「行号 + 类名 + 方法名」三件套最脆：`29` 条 A 类里有 19 条是行号或测试名。→ 闸门 8（`scripts/check-doc-refs.sh`）把每条引用拿项目 / 上游 / JDK 三处解析一次。
3. **跨章承诺必烂尾。** 「第 14 章会自己变红」「第 02 章会把名字改回去」——写的时候是真的，后来没人回头。→ 闸门 10（章节交叉引用主题校验）。
4. **空断言必混进来。** 13 条 E 类里最多的形状是 `assertThat(x).isSameAs(y)` 在双方皆 null 时恒真（ch06 / ch09 / ch17 / ch22 / ch34 各一条）。**这类缺陷只有变异才能发现**：把被测方法改成 `return null` 还绿的测试，就是没有测试。
5. **同义术语必裂开。** 「早期引用 / 提前引用」「通知 / 增强 / Advice」「壳 / 代理」在 35 章里各分裂过一次。GLOSSARY 是唯一来源，但**首现处从不链接它**——这条已进缺陷清单。

## 三、值得直接借鉴的八件事（正面）

1. **同一个接口逐章长大**：`NaiveContainer`（100 行）→ …… → `DefaultListableBeanFactory`（1170 行），接口不变，实现逐章加深。深模块的教学法不是「讲接口」，是**让读者看着接口撑住 11 次加料**。
2. **守卫的位置和守卫本身一样重要**：`PropertyPlaceholderHelper` 的循环引用守卫写对了，却因为 `finally` 里清空 `visited` 而死循环。修法不是「再加一个守卫」，是**把「把值解析完」挪到名字还在 `visited` 里的时候**（ch10 §4.3）。
3. **谁跑到锁外，谁就必须是并发容器**：一句话同时约束业务代码（`getEarlyBeanReference` 移出创建锁）和框架自己的登记表（ch31 把 `proxiedBeanNames` 换成 `ConcurrentHashMap.newKeySet(16)`）。
4. **用 `remove` 的返回值当令牌**：`ConcurrentHashMap#remove` 只有一个线程能拿到非 `null`，「互斥已经由数据结构的原子性提供了」，不需要再加一把锁（ch31 `DefaultSingletonBeanRegistry:222`）。
5. **异常链留两层**：`BeanCreationException` 的 `cause` 是「真正的原因」，`relatedCauses` 是「其余线索」（如三个候选各失败一次）。新手最容易只留一层，然后在真实项目里丢现场。
6. **每个 `public` 类都交代「砍掉了什么」并 `@see` 真实 Spring 全限定名**：`docs/CODE-STANDARDS.md` 的三件套。这条让「这是简化」和「这是我编的」在版面上就分得开。
7. **把旁证交给机器，把判断留给人**：9 道闸门里，4 道是本次评审新建的（propagation 单边检测、doc-refs、doc-tables、章节交叉引用）。结论：**评审的价值不在「我读了一遍」，在于把这次的错误变成下次跑一次就能发现的东西。**
8. **驳回要留证据**：全书共驳回 5 条专家意见，其中 4 条是「术语视角把『我没见过』当成『不存在』」。评审报告必须记「被驳回的意见 + 反驳依据」，否则下一轮还会被同一条假问题占用时间。
