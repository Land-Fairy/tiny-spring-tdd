## P1

- `docs/chapters/18-resource-pattern.md:69`：写 `[INFO] 7 errors`，下面只列了 6 条。
- `docs/chapters/18-resource-pattern.md:100`：栈帧行号 `:112`，实际 `:125`。
- **V6**：`PathMatchingResourcePatternResolver` 的目录递归用 `File.listFiles()`，没有 visited 集合也没有深度上限。`ln -s .. loop` 这种目录在 `**/*.class` 模式下会把栈打穿——不是理论问题，是 `find / -L` 的老坑。
- **V6**：`setUseCaches(false)` 只对本次拿到的连接生效，jar 内的 `JarFile` 句柄仍常驻。在容器里反复扫描会攒 fd，文档把这段讲成了「已修」。
- **V4**：`PathMatcher` 接口只有一个实现、且被 `private final` 字段直接 `new`，「可替换」是假的（同 `ch04` 的 `InstantiationStrategy`）。

## 读者会在哪放弃

`AntPathMatcher` 的 `**` 与 `*` 语义差异只靠一段散文解释，没有一张「表达式 × 路径 → 是否匹配」的表。读到第 3 个 `**` 例子时放弃。

## 总判词
