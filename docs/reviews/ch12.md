## 三、P1

1. `docs/chapters/12-aware.md:357-366` 给出 XML 片段并说「于是它可以写进 XML」，但没交代这段其实是 `src/test/resources/ch12/autowired.xml`（由 `ApplicationContextAwareTests.java:56` 加载）。读者会把测试资源当成生产配置。
2. `step-12-…/samples/ch12/NeedyService.java:30`、`:38` 两个访问器全书零调用。
3. `AwareCallbackOrderTests.java:56-65` 与 `ApplicationContextAwareTests.java:40-52` 断言同构（E2），前者成立与实现无关。
4. 「设施消费者」（`:320`）是自创词，词表里只有「容器设施」。

## 四、读者会在哪一段放弃

开篇第一个示例。这一章开头就要讲「后处理器是怎么被装进容器的」，而示例本身编译不过——读者会先怀疑自己的 IDE，再怀疑 JDK 版本，最后才怀疑书。已修。

## 五、总判词

本章把 `Aware` 讲成「容器与 Bean 之间的双向契约」：Bean 声明「我愿意接收什么」，容器在初始化早期把对应设施递过去——这个角度是对的，`ApplicationContextAwareProcessor` 用「鸭子类型 + `instanceof` 分派」实现它，41 行就够。失分在两处**口径**：`prepareBeanFactory` 的注释说了三件互斥的事（C1）；`ApplicationContext` 递出去的能力比正文承诺的少一个 `getEnvironment()`（C2）。后者是设计取舍（深接口 vs 可用性），应当在正文里明说「本书故意把上下文接口做窄」。
