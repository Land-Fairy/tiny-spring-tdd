## 三、P1（择要，逐章会重复出现）

1. **`register` 一词三义**：注册（`register(String,Object)`）/ 装配（`wireXX()`）/ 取用（`getBean`）。真实 Spring 里「成品」和「图纸」是两个名词（单例对象 / BeanDefinition），本章只有 Map 里那一个东西，概念未命名 → 第 02 章才补。建议章末一句话预告（知识图谱工程师）。
2. **`size()` 泄漏实现契约**：真实 Spring 叫 `getBeanDefinitionCount()`；`size()` 不说清"数的是什么"。异常只有 message、没有 `getBeanName()`/`getBeanType()`，测试只能 `withMessageContaining` → 契约退化到字符串匹配（API 平台工程师）。
3. **类注释缺固定措辞**：`NaiveContainer.java:8-28`、`NoSuchBeanException.java:3-15` 都没有「它砍掉了什么：」字样，而 `docs/CODE-STANDARDS.md:187` 定为固定措辞——**本章核心类反而没有**（技术文档工程师）。
4. **GLOSSARY 缺口**：`ListableBeanFactory`、`ConfigurableListableBeanFactory`、「多例」未收录（技术文档工程师）。
5. **改名后语义不成立**：`getBean(Class)` 名字承诺"那个 Bean"，行为是"随便第一个"（技术文档工程师）。
6. **代理语义文档互斥**：`doc:454-456` 与 `appendix B:165-166` 说法相反（spring-reviewer）。
7. **生产视角的连带故障**：两请求线程共用一个 `GreetingController` → `ArrayList history` 无同步 → 丢更新/`ArrayIndexOutOfBoundsException`；随后 `:45` 的 `List.copyOf` 读到含 null 数组抛 NPE，**栈顶在 45 行而非 50 行**，排查方向会跑偏（后端架构师）。

## 五、对本章的总判词

**骨架是对的，注释在撒谎。** 94 行讲清「一个 Map + 反射 + 一个异常 = 容器的全部真相」，这个选材本身无可指摘，5 个公开方法与真实 `BeanFactory` 同名同义，第 01 章该教的东西一个没漏。问题全部集中在**旁证**上：指向不存在的类、编造的 stack trace、说错的辅助结构数量、兑不了的下章承诺。对一个"让新手照抄"的仓库，旁证造假比设计缺陷更致命——设计缺陷读者能自己发现，旁证造假读者只会怀疑自己。

修法全部是局部文本替换，不动设计。15 条 P0 修完，本章可判 PASS-WITH-FIXES → PASS。
