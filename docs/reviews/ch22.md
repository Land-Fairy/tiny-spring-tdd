## P1

- 扫描器的类注释在三章里逐字复制，都写「本章只支持目录（不支持 jar）」。到了第 22 章已经有 jar 支持了，注释还留在原地——**跨章复制的注释会追不上代码**（同 ch13/ch15 的问题）。
- `docs/chapters/22-assembly-control.md:79` 残留「（本次修订补上）」——评审痕迹进了正文。
- **V6**：`ConfigurationClassPostProcessor.java:173-184` 用 `Class.forName(className)` 在**注册阶段**加载配置类：① 不用容器的类加载器；② 触发静态初始化。条件是「导入一个还没加载的类就会中招」。
- **V6**：`ProfileCondition.java:33` 用 `Set.of(getActiveProfiles())` 判重——同时激活两个同名 profile（`-Dspring.profiles.active=a,a`）会抛 `IllegalArgumentException: duplicate element`。上游用的是 `Arrays.asList().contains()`。
- **V6**：`ConditionEvaluator.java:45-52` 每次求值都 `newInstance()` 一个条件类，没有缓存。配置类多的时候是纯粹的重复反射。

## 读者会在哪放弃

「四张牌」的比喻打得好，但 4 个特性（`@Import` / `@Conditional` / `@Profile` / `@Lazy`）各占一节，节间没有一张「它们在同一棵树上的位置」的图。读者到第 3 节开始记混谁依赖谁。

## 总判词

结构最像「真正框架」的一章：`ConfigurationClassPostProcessor` 是一个有明确输入输出的深模块。**问题全在证据层**——测试数、上游行数、跨章注释三处都不实。修完 E1/B1-B3 后可跟。
