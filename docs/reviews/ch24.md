## P1

- `docs/chapters/24-jdk-proxy.md:176` 「第 4.4 节的 `expectedDumpFile`」——该方法在 §3.4（`:320`）。**已修**。
- **V4**：`aop/framework/AopProxy.java:6-7` 说第 26 章会用到这个接口，但 `AbstractAutoProxyCreator.java:131` 只 `new ProxyFactory`，唯一实现被 `ProxyFactory.java:40` 写死。「接口 = 可换实现」是假抽象（同 ch18 的 `PathMatcher`、ch04 的 `InstantiationStrategy`，这是本书的一个**重复病灶**）。
- **V6（必须写明）**：`JdkDynamicAopProxy.java:103` 把拦截器链组装放在 `try` 之外，`DefaultAdvisorAdapterRegistry.java:44` 遇到未知 `Advice` 抛异常 → `finally` 不执行 → 池化 `TargetSource` 每次调用漏一个目标（专家实测：3 次调用 `getTarget=3`、`release=0`）。`TargetSource.java:43` 那句「放在 finally 里调用」的承诺因此不成立。
- **V3**：`ProxyDiagnosticsTests` 三条全哑——`sameProxyClass` 返回常量 `true` 后 0 条红；`savingIsEnabledByTheBuild` 只断言 `user.dir` 是目录（恒真）；`theSameInterfaceCombinationReusesOneProxyClass` 缺「不同接口组合应为 false」的反向样例。
- **V6（教学可接受）**：`ReflectiveMethodInvocation.java:34,56` 每个拦截器 +2 帧，链深即栈深；`index` 只增不回退，二次 `proceed()` 会直打目标并静默跳过剩余增强。

## 读者会在哪放弃

第 4 节让读者自己去 `javap` ——这是全书最好的「亲手验证」设计。但如果照着写好的路径找不到文件，这个设计就变成了挫败源。**修 D1 后这一节从「劝退点」变成「亮点」**。

本章是全书 bytecode 教学的入口，`$Proxy` 类的骨架、方法体、异常表三段引文都是逐字对得上的硬材料。修完 A1/D1 后可以放心照着做。
